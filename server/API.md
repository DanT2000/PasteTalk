# API PasteTalk

Два разных интерфейса, и путать их не надо:

| | Где живёт | Кому |
|---|---|---|
| [Серверный](#серверный-api) | `https://ваш-сервер` | Телефону, боту, слабому компьютеру |
| [Локальный](#локальный-api-движка) | `http://localhost:порт` на вашем ПК | Вашим программам на том же компьютере |

Всё общение — JSON. Ошибка приходит как `{"error": "по-русски, что случилось"}`
с кодом 4xx или 5xx.

---

## Серверный API

### Как получить доступ

Владелец выдаёт в админке **шестизначный код**. Код одноразовый и живёт
заданное время (по умолчанию десять минут). Меняете его на постоянный токен —
дальше ходите с токеном.

```http
POST /v1/activate
Content-Type: application/json

{ "code": "123456", "kind": "android", "title": "Redmi Note 12" }
```

| Поле | Обязательно | Что это |
|---|---|---|
| `code` | да | Шесть цифр из админки |
| `kind` | да | `android`, `telegram` или `desktop` |
| `title` | нет | Как назвать устройство в админке |
| `externalId` | нет | Номер в Telegram, если `kind` = `telegram` |

```json
{ "token": "5mGAAvsN9CYOLiXSA4vjb6qOu7C7-lSa8UD0WdNOtFA" }
```

Токен постоянный — храните его. Дальше он идёт заголовком:

```
Authorization: Bearer ВАШ_ТОКЕН
```

Ошибки: `403` — кода нет, устарел или слишком много попыток; `400` — неизвестный
вид устройства.

### Распознать речь

```http
POST /v1/transcribe
Authorization: Bearer ВАШ_ТОКЕН

{ "audio": "<base64>", "filename": "voice.wav", "language": "ru", "seconds": 12 }
```

| Поле | Обязательно | Что это |
|---|---|---|
| `audio` | да | Звук целиком, в base64 |
| `filename` | нет | Расширение подсказывает формат. По умолчанию `voice.ogg` |
| `language` | нет | `ru`, `en`… Пусто — определит сам |
| `seconds` | нет | Длительность. **Присылайте её** |

Про `seconds`: провайдеры её возвращать не обязаны, а без неё расход считается
нулём. WAV сервер измерит сам по заголовку, остальное — нет.

```json
{ "text": "Проверяем, что программа работает", "seconds": 5.97, "where": "agent" }
```

`where` — кто считал: `agent` (домашний компьютер владельца, бесплатно) или
`cloud` (облако, за деньги).

Ошибки: `401` — токен неверный или доступ отозван; `400` — нет звука;
`502` — не удалось распознать, текст ошибки объясняет почему.

Предел тела запроса — **96 МБ**. Учтите, что base64 больше исходника в 1.33 раза,
а облачные провайдеры обычно режут файл на 25 МБ.

### Причесать текст

```http
POST /v1/improve
Authorization: Bearer ВАШ_ТОКЕН

{ "text": "ну это самое короче программа работает и вот", "mode": "both" }
```

| `mode` | Что делает |
|---|---|
| `clean` | Убирает «эээ», повторы, оговорки. Слова остаются ваши |
| `both` | То же плюс переписывает письменным языком: абзацы, связные фразы |

```json
{ "text": "Программа работает.", "where": "cloud" }
```

Сервер текст у себя не хранит — присылайте его целиком каждый раз.

### Состояние

```http
GET /v1/state
Authorization: Bearer ВАШ_ТОКЕН
```

```json
{ "ok": true, "agentOnline": true, "agentName": "Samuray" }
```

Требует токен намеренно: включён ли домашний компьютер — это расписание
владельца, и посторонним знать его незачем.

### Жив ли сервер

```http
GET /health
```

```json
{ "ok": true }
```

Единственная ручка без токена.

## Протокол агента

Домашний компьютер сам подключается к `wss://ваш-сервер/agent` и держит
соединение. Сервер к нему не стучится — ничего пробрасывать на роутере не нужно.

Агентом может стать только профиль, которому владелец **разрешил это в админке**
кнопкой «агент». Одного токена мало: вид устройства выбирает сам клиент.

Компьютер здоровается:

```json
{ "type": "hello", "token": "ТОКЕН", "name": "Samuray" }
```

Сервер отвечает `{"type":"welcome"}` — или `{"type":"denied","message":"…"}` и
закрывает соединение.

| Направление | Сообщение | Смысл |
|---|---|---|
| сервер → ПК | `{"type":"ping"}` | Каждые 20 с. Молчит 60 — считаем отвалившимся |
| ПК → сервер | `{"type":"pong"}` | Живой |
| сервер → ПК | `{"type":"job","id":"…","kind":"stt","payload":{"audio":"<base64>","filename":"…","language":"ru"}}` | Распознать |
| сервер → ПК | `{"type":"job","id":"…","kind":"llm","payload":{"text":"…","mode":"clean"}}` | Причесать |
| сервер → ПК | `{"type":"job","id":"…","kind":"ping"}` | Проверка связи из админки |
| ПК → сервер | `{"type":"result","id":"…","result":{…}}` | Готово |
| ПК → сервер | `{"type":"error","id":"…","message":"…"}` | Не смог, с причиной |

Ответ на `stt` — `{"text":"…","seconds":12,"model":"large-v3"}`, на `llm` —
`{"text":"…","tokensIn":0,"tokensOut":0,"model":"…"}`, на `ping` — `{"pong":true}`.

## API админки

Заводского пароля нет. Пока панель свободна, `GET /admin/state` отвечает
`{"claimed": false}`, и первый пароль назначается так:

```http
POST /admin/setup
{ "password": "…" }
```

В ответ сразу приходит сессия. Второй раз занять уже занятую панель нельзя.

Вход даёт сессию на 12 часов. Она живёт в памяти сервера: перезапуск её
сбрасывает.

```http
POST /admin/login
{ "password": "…" }
```

```json
{ "session": "…", "mustChange": false }
```

Дальше заголовком `X-Admin-Session: …`. Ответ `401` — войдите заново.

| Метод и путь | Что делает |
|---|---|
| `POST /admin/password` | Сменить пароль. `{ "password": "…" }`, не короче 8 знаков |
| `GET /admin/api/people` | Профили с кодами, устройствами и расходом |
| `POST /admin/api/keys` | Завести профиль. `{ "name": "Мама, телефон", "ttlMs": 600000 }` |
| `POST /admin/api/keys/:id/code` | Выдать новый код тому же профилю |
| `POST /admin/api/keys/:id/serve` | Разрешить быть агентом. `{ "allowed": true }` |
| `POST /admin/api/keys/:id/bind` | Привязать Telegram вручную. `{ "externalId": "123456789" }` |
| `DELETE /admin/api/keys/:id` | Отозвать профиль — все его устройства сразу |
| `DELETE /admin/api/devices/:id` | Отвязать одно устройство |
| `GET /admin/api/spend` | Расход за месяц, по дням и по моделям |
| `GET /admin/api/agent` | Состояние домашнего компьютера |
| `POST /admin/api/agent/ping` | Спросить компьютер и замерить ответ |
| `GET /admin/api/settings` | Настройки. Секреты приходят как `***` |
| `POST /admin/api/settings` | Сохранить. Пустое поле секрета — «не трогали», `-` — стереть |
| `POST /admin/api/proxy/check` | Проверить прокси через настоящий запрос к Telegram |

## Локальный API движка

На компьютере с PasteTalk работает распознающий движок. Он слушает **только
`localhost`** и наружу не смотрит — им могут пользоваться ваши программы на том
же компьютере.

Адрес виден в **Настройки → Интеграция → Локальный адрес движка**. Порт по
умолчанию случайный; постоянный задаётся в **Основных**.

Каждый запрос требует одноразовый токен сессии — он рождается при запуске
движка и печатается в его первую строку вывода:

```
PASTETALK_ENGINE {"port": 51487, "token": "…", "pid": 1234, "version": "2.3.0"}
```

Заголовок: `X-PasteTalk-Token: ТОКЕН`.

| Метод и путь | Что делает |
|---|---|
| `GET /health` | Жив ли движок |
| `GET /model` | Какая модель загружена и на чём считает |
| `POST /model` | Загрузить. `{ "name": "large-v3", "device": "cuda", "computeType": "float16" }` |
| `DELETE /model/:name` | Удалить скачанную модель |
| `POST /benchmark` | Замерить скорость на этой машине |
| `POST /file` | Распознать файл. `{ "path": "C:/…/zapis.mp3", "language": "ru", "timestamps": false }` |
| `GET /file/:id` | Как идёт распознавание файла |
| `DELETE /file/:id` | Бросить |
| `POST /session` | Начать поток. `{ "language": "ru" }` → `{ "id": "…" }` |
| `POST /session/:id/audio` | Дослать кусок звука, сырой PCM 16 кГц моно |
| `POST /session/:id/stop` | Закончить и получить текст |
| `DELETE /session/:id` | Бросить запись |

Потоковый путь (`/session`) режет речь по паузам и распознаёт на ходу; файловый
(`/file`) берёт запись целиком. Для своих программ проще второй.

---

## Что сервер не хранит

**Ни звука, ни распознанного текста.** В базе только счётчики: кто, когда,
сколько секунд, где считали и во сколько обошлось. Это не обещание на словах —
в таблице `usage` просто нет столбцов, куда такое можно было бы положить.

Поэтому `POST /v1/improve` и принимает текст целиком: достать его серверу
неоткуда.
