# Агенты отдельно от людей

Дата: 2026-08-06
Состояние: согласовано, к реализации
Опирается на: [ядро сервера](2026-08-05-pastetalk-server-design.md)

## Зачем

Сейчас компьютер-агент — это профиль человека, которому в админке поставили
галочку «агент». Две разные сущности живут в одной таблице и в одном списке:

- **человек** диктует, тратит минуты, у него код доступа и устройства;
- **компьютер** ничего не диктует, он считает за других.

Из-за этого нельзя ответить на простые вопросы: сколько у меня компьютеров,
кто из них сейчас работает, кого спрашивать первым. И нельзя добавить второй
компьютер, не заведя фиктивного «человека».

## Что меняется

Своя таблица `agents_v2`, свой раздел админки, свой способ подключения.

| | Человек | Компьютер |
|---|---|---|
| Заводится | «Люди» → выдать код | «Компьютеры» → добавить |
| Чем подключается | Разовый шестизначный код | Постоянный ключ агента |
| Что видно | Минуты, рубли, устройства | На связи, отклик, сделано задач, очередь |
| Зачем нужен | Диктует | Считает за других |

Профиль человека агентом больше не бывает. Поле `may_serve` уходит.

## Ключ агента

Не одноразовый код, а **постоянный ключ**, который владелец выдаёт в админке и
вставляет в PasteTalk на компьютере. Разница с людьми осознанная:

- компьютер подключается один раз и живёт годами — разовый код тут только
  мешает;
- ключ виден в админке всегда, его можно скопировать заново, не трогая связь;
- отзыв ключа снимает компьютер с линии сразу, как сейчас.

Формат — длинная случайная строка, показывается целиком (это не пароль
человека, а настройка машины).

## Несколько компьютеров

У каждого свой **порядок**: 1, 2, 3. Спрашиваем по возрастанию.

```
задача → компьютер №1 на связи? → да → ждём ответа
                                 → нет → компьютер №2 → … → облако
```

**Ожидание отмеряется отдельно для каждого.** Если №1 не взялся за дело за
`SPILL_MS` (сейчас 30 секунд), задача уходит не сразу в облако, а следующему —
и только когда кончились все, в облако. Это и есть «минимальное время
ожидания», о котором просил владелец.

Очередь у каждого компьютера своя: один держит одну модель в видеопамяти, но
два компьютера — это два одновременных распознавания.

«Кто взял, тот взял» отвергнуто в пользу порядка: без него задачи растекались
бы случайно, и понять, почему диктовка ушла на медленный ноутбук вместо
мощного ПК, было бы нельзя.

## Раздел «Компьютеры»

Список, по строке на машину:

| Имя | Порядок | Состояние | Отклик | Задач | Ключ | |
|---|---|---|---|---|---|---|
| Домашний ПК | 1 | на связи | 169 мс | 42 | скопировать | пинг · вверх · удалить |
| Ноутбук | 2 | не на связи | — | 7 | скопировать | пинг · вниз · удалить |

- **Пинг** — как сейчас: настоящий запрос к машине с замером.
- **Вверх/вниз** — менять порядок.
- **Ключ** — скопировать, чтобы вставить в PasteTalk.

Сверху — общее: сколько машин на связи, сколько задач в очереди прямо сейчас.

## Протокол

Не меняется, кроме рукопожатия: вместо токена устройства — ключ агента.

```json
{ "type": "hello", "key": "…", "name": "Samuray" }
```

Отказ по-прежнему `{"type":"denied","message":"…"}`.

## Переход со старого

У кого уже есть профиль с `may_serve` — при обновлении из него заводится
компьютер с тем же именем и новым ключом, а сам профиль остаётся человеком без
права служить. Владелец увидит в журнале строку с новым ключом и вставит его.

Молча оборвать связь нельзя: человек не поймёт, почему компьютер отвалился
после обновления.

## Что проверяется

- Второй компьютер подключается, не мешая первому.
- Задача уходит первому по порядку; он молчит — второму; молчат все — в облако.
- Порядок меняется, и следующая задача идёт по новому.
- Отзыв ключа снимает машину с линии сразу.
- Ключ человека агентом больше не работает.
- Два компьютера с одним ключом: второй отвергается, а не вытесняет первого.

## Границы

Не входит: распределение по загрузке, разные модели на разных машинах, выбор
машины человеком, статистика по каждой машине в разделе «Расход».
